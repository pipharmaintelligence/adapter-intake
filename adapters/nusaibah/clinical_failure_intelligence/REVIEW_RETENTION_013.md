# Bounded Clinical review and complete-output retention

## Clinical0.1.13

The hypothesis plan can grow after adjudication returns derived context. A
fixed one-call review reserve can exhaust the call budget before the critic
phase. Version0.1.13 reserves a bounded review phase before further hypothesis
dispatch. Optional memory/recovery floors leave at least one possible critic
call when any calls remain. The same overall call, time, reconciliation,
reflection and concurrency limits still apply. Unexecuted assignments remain
explicit deferred work; a model success does not certify a scientific claim.

Large deferred packets share identical context through digest-verified
`$context` references into the assessment's existing objects map. Hydration
restores the exact original packet digest before any future execution. Literal
reference-shaped business data is escaped. Missing, changed or cyclic context
fails closed. Complete scientific passages, support polarity, source digests,
candidate scope, task IDs and no-replay flags are preserved. Prior versioned
implementations and manifest entries remain unchanged; the output node schema
is still1.2.2. Nothing here grants paid continuation or memory write authority.

## SDK147 / Core / Assets

Preview retention budgets cover the complete outputs envelope, including
duplicate representations of the same clinical DTO. A published node object
can exist even when the separate preview exceeds its signed limit. Publication,
preview retention, result availability and scientific quality must be reported
independently. Never reconstruct a missing original multi-role preview from
one published role or rerun paid analysis merely to obtain it.

SDK147 keeps the legacy8MiB compatibility constant and adds an explicitly
signed32MiB tier alongside1/4/8MiB. Core's default behavior and ordinary artifact
budgets are unchanged. The server-owned `DLM_WORKFLOW_PREVIEW_MAX_BYTES=33554432`
option applies only to preview-kind artifacts. An intended Assets consumer can
then sign that tier with `DLM_PREVIEW_RESULT_MAX_BYTES=33554432`. Leave other
consumers unchanged. Install the matching SDK before enabling the larger tier;
an incompatible or insufficient Core preflight blocks before provider work.

Readback still checks exact client/run/asset identity, expiry, size and checksum.
The32MiB ceiling remains finite. No role is silently omitted or truncated, and
size warnings do not negate an acknowledged node publication. Core owns all
storage and credentials; the adapter receives no transport authority.

## Qualification and rollout

Run synthetic large dual-role store/read/verify tests; verify ordinary artifact
limits still reject oversized payloads. Test both old8MiB and explicit32MiB
instructions, tampered scope/checksums and deferred-packet round trips. Build
and scan wheel/sdist artifacts and regenerate ECS attestations from that wheel.

Before enabling32MiB, qualify the selected HTTP route with enough body capacity
for44,739,244 base64 characters plus JSON overhead (normally a64MiB body limit),
as well as PHP/proxy memory and time budgets. Preflight explicitly does not
attest proxy body limits or future generated output size. This release does
not deploy cloud ECS, change source/input bindings, alter the output node,
restart unrelated workers, authorize paid retries or certify clinical accuracy.

A canonical-size warning alone does not downgrade completed scientific quality.
Scientific gaps remain partial; runtime retention and publication remain separate
states with their own receipts and limits.
