# Clinical 0.1.8 scientific completion repair

## Confirmed defects
The retained 0.1.7 run completed transport successfully but generated no hypotheses.
Global outcome-reference closure repeated 278 windows before any assigned window;
every singleton exceeded both the admitted character and adapter byte budgets.
Three researcher items failed literal span checks and nine critic verdicts added
references outside their candidate's closed evidence sets. These remain scientific
validation errors, not reasons to discard valid work or certify unsupported claims.

## Implemented contracts
- Full source windows, research claims and outcomes remain once in canonical output.
- Hypothesis packets carry complete assigned source windows and complete selected
  research claims, plus a complete provisional outcome identity/value index with
  canonical digests. The index is not evidence and cannot grant acceptance.
- An unfit common packet produces one explicit deferred work unit, not one per row.
- Critic schemas constrain support and counterevidence separately for each candidate.
- At most four explicit business correction tasks per run, once per rejected unit,
  only when enable_refinement=true; every call shares the existing 64-call budget.
  Original stage outputs/digests and correction lineage remain auditable. Corrections
  pass the same validators. No provider-unknown-outcome or security retry is added.
- Product memory preview uses complete already reviewed derived findings, exact
  source IDs and a canonical ledger digest. It has no raw-source or new-science
  authority. Editorial batches preserve whole old paragraphs, check new text against
  scoped reviewed findings and independently review each edit. Aggregate edit limits,
  target collisions, deduplication and existing digest guards remain enforced.
- No source configuration, Core policy, credential, Dynamic Skill write, publication
  or clinical success probability is changed. Models, thinking levels, fixed Skill,
  reflection bounds, source adapter versions and local_worker/ECS manifests persist.

## Qualification boundary
Provider-free tests and saved-run packet measurements establish engineering behavior.
They do not establish future model quality, scientific accuracy or live deployment.
Promotion, new Agent 1.6.0 admission, source bindings and a separately authorized live
run remain release gates. Execution success is distinct from clinical quality.


## PR #164 extension: scoped Gemini-4 input retry

The optional eighth role `input_reconciler` uses `gemini-4-argon`, high thinking,
16000 output tokens and no public search. It prepares one affected input fragment
for the original role; it does not replace the researcher, adjudicator, analyst,
scientific critic or memory editor. All eight Agent 1.6.0 prompt digests require
fresh admission for this unmerged candidate. Previous published versions stay frozen.

Eligible shape/citation/reference/enum errors are sent with only their rejected
identities, exact error codes, necessary complete evidence windows and dependency
context. Valid siblings and the full case payload are excluded. Proposed citation
spans must preserve source identity and exact text/digest; proposed critic reference
sets cannot expand or change polarity. Scientific statement rewrites are rejected.
The original role then processes the prepared fragment once, and all existing
validators and independent reviews still apply. An unresolved proposal is usable
diagnostic evidence, never automatic scientific acceptance.

An undispatched oversized input may be sent as an immutable unit-ID/size/digest
inventory. The model can propose at most two groups. Code requires every assigned
unit exactly once, reconstructs each request from the original whole source rows
and dependency closure, and measures every group against both admitted limits
before dispatch. Atomic/shared-context oversize, missing units and invalid plans
remain explicitly deferred. Reconciliation cannot truncate or rewrite source text.

Bounds: enable_refinement=true; one pass per original task; at most four affected
tasks, eight total reconciliation/original-role retry invocations, two partition
groups per task, all inside the existing 64-call limit, deadline, concurrency and
downstream completion reserves. This optional path has no recursive JSON/recovery
loop. Successful unchanged tasks do not invoke it. Canonical child outputs remain
retained and execution includes reconciliation stages, receipts and explicit joins.

IAM/authentication, security/policy rejection, unknown dispatch outcomes, missing
admission, resource exhaustion and unsupported error codes do not acquire retry
permission. Scientifically legitimate inconclusive/withheld findings are not data
format errors and are not upgraded by this role. No full workflow or paid batch is
automatically resubmitted; no source, credential, memory or publication is changed.
