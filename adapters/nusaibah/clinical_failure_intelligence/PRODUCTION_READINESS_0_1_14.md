# Clinical 0.1.14 production preparation

This release bounds analysis to 3,600 seconds and 64 logical Agent calls per case. Its execution manifest allows 4,200 seconds; the dedicated Assets consumer allows 4,500 seconds with one try. Runtime authority, provider deadlines and shared capacity remain independently enforced. Existing 0.1.13 and earlier modules and manifest versions remain byte-for-byte unchanged.

Before optional hypothesis waves, the planner measures complete critic packets for the actual known candidates, protects that review cost, then admits small hypothesis waves. Each new hypothesis call can return at most four candidates, enforced in the actual response schema and decoder. Unadmitted packets remain explicit deferred work. This bounds expansion without dropping source windows, weakening citations or claiming omitted work was completed.

Critic continuation uses deterministic first-fit complete packets, restricted to selected pending IDs. It retains all dependency records and original source text. An offline replay of signed 0.1.13 output selected 32 of its 34 unreviewed candidates: the new planner produced five fitting review packets versus 32 calls in the prior continuation path. This is a planning result, not a new scientific review. The original result, publication and unresolved findings remain intact.

When a valid critic response omits an assigned verdict, one correction may request only those missing IDs. Valid siblings are retained; there are at most two such corrections per case, no recursive retry, and the shared case budget still applies. Malformed identities, duplicate verdicts, unsupported citations and unresolved dependencies remain subject to strict deterministic validation.

The eight Agent 1.7.0 role contracts and methodology Skill stay unchanged. The new optional `previous_assessment_013` role accepts only the exact Core-governed retained Clinical 0.1.13 output identity. Saved data does not authorize execution, scientific acceptance, publication or memory writes. Reflection stays limited to one round/two tasks/four Agent calls. Input reconciliation remains bounded by the existing four business repairs/eight reconciliation calls, within the total 64-call budget.

## Validation and release gates

- Provider-free regressions cover known review reservation, bounded candidate schemas, successful and unresolved missing-verdict correction, selected continuation batching, forged retained authority, source drift and immutable old versions.
- Core/runtime safe diagnostics use a negotiated protocol; legacy workers retain existing behavior. Unknown outcomes remain held for reconciliation.
- SDK 0.1.148 adds exact signed retained-output versus current canonical node validation and a once-only operator guard. The destination node must explicitly admit 0.1.14; an old-version successful result is insufficient.
- Production hosting must use the opt-in 32 MiB preview/64 MiB HTTP body/PHP 8.4 profile, bounded PHP children and two signed worker slots. Configuration validation alone does not certify a deployment.
- After promotion: register/admit the exact package and eight roles, approve the same governed binding and publish-policy scope, apply the reviewed additive node contract, qualify two concurrent signed model-free runs, then obtain separate approval for a bounded paid run and verify its actual retained result and provider publication readback.
- ECS requires a real digest-pinned image, reviewed task resources/network/roles/secrets, migration and configuration-cache readiness, controlled signed smoke, graceful drain and a recorded rollback revision. No cloud deployment or additional paid call is claimed by this change.

Partial scientific results remain partial even when safely retained and published. Source gaps and the remaining unselected reviews must be addressed through explicitly selected, newly admitted follow-up work.


## Cross-version source snapshots and exact record qualification

A newly approved asset-version binding has a different `aib_` ID. Continuation may record that ID transition only when the complete file checksum, row count, access mode, case and evidence remain identical. Current Core binding authority is still required; the saved result grants none. Missing/incomplete/changed snapshots and arbitrary source references are rejected. The old evidence/provenance remains preserved with an explicit transition receipt.

Ordinary `preflight_only=true` returns a semantic preflight report, not a publication record. The exact model-free record proof uses the existing governed retained-finalization path: `finalize_only=true`, `resume_work_ids=[]`, `preflight_only=false`, `prepare_result_for_persistence=true`, `memory_mode=off`, and refinement/search/classification disabled. It produces `clinical_intelligence_records` with zero Agent calls and explicit `scientific_processing_repeated=false`. It preserves the source result's partial quality and cannot authorize publication or paid work. Signed serving qualification must receive `previous_assessment_013` through Core, never a caller-created envelope.
