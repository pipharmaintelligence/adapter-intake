# Clinical 0.1.15 candidate-scope recovery

A model-produced outcome with a trial ID outside the governed case previously raised through the candidate normalizer and terminated the whole analysis. The affected-input reconciliation path was never reached. This version isolates invalid model candidates, keeps valid siblings, and retains the exact rejected candidate and its reason in the deferred-work object store. Governed input subject, event, trial and source authority remain strictly validated before Agent work.

The actual outcome response schema enumerates the case's approved trial IDs. An empty approved set permits only an empty array. Research discovery or literature mentions cannot add an approved case association. No model is asked to manufacture missing trial authority: an empty case trial set produces an explicit unresolved reconciliation receipt without spending correction calls.

Where the case already has approved trial IDs, an affected candidate may use the existing one-pass input-reconciler plus original-role correction, within the unchanged four business repairs, eight reconciliation calls, 64 total logical calls and 3,600 analysis seconds. Only rejected identities and their scoped evidence are supplied. Invalid corrections stay deferred; a definitive claim cannot be repaired merely by removing its trial identifiers. Retry errors are mapped back to the original candidate index so they cannot quarantine a valid sibling. Duplicate model IDs quarantine the ambiguous candidates while preserving other unique candidates.

Unresolved candidate validation marks its stage and required role partial. The result remains eligible for governed partial-result staging with rejected/deferred receipts preserved; Python does not write or attest provider publication. Scientific acceptance still requires the critic's evidence and scope checks. No new retry authorization is granted by a saved candidate or packet.

All 0.1.14 modules, support files and its manifest entry are frozen. The new immutable entrypoint/helpers/schema use 0.1.15. Eight existing Agent 1.7.0 contracts and the methodology Skill remain unchanged. No installed runtime, Core credential, node, serving worker or company launcher is changed by this intake package.

## Verification

Provider-free regressions cover empty and finite trial schemas, one and five out-of-scope candidates, preservation of valid siblings, bounded successful/invalid corrections, qualifier stripping, malformed correction identities, correct subset-index mapping, duplicate model IDs, wrong model subjects, strict governed-input scope, call-budget exhaustion, output schema validation, publication-record preparation and immutable historical versions. The private retained-response replay is diagnostic evidence only; raw provider records and internal operational reports are not part of this public package.

Promotion/delivery, new-version registration/admission/bindings, additive output-node identity approval, signed execution and actual publication readback remain deployment gates. A provider-free test is not a new paid run or scientific certification.
