# Contained business validation

The 0.1.46 company-13 execution reached a research repair whose inference
preservation check rejected the backup. The v0.1.17 validator throws
ResearchContractValidationError; the research handler catches the unrelated
v0.1.26 ResearchResponseContractError. That error escaped the shared scheduler,
aborting the workflow before synthesis and publication despite completed siblings.

Version 0.1.47 gives the existing chunk scheduler one explicit boundary for the
concrete business-validation exception classes used by research, criticism and
presentation. A rejected work item becomes unresolved with its exact
role/stage/field/rule and packet location. Independent completed items retain
their original order and flow through the existing consolidation, evidence
checks, profile rendering and Core Skill publication. There is no extra Agent
call, relaxed validation, fabricated replacement evidence, or budget increase.

The 0.1.46 non-object synthesis fix and existing publication fallbacks remain
active. Reviewed evidence retains its verification; eligible draft research
retains explicit unverified labels. If no usable research survives, the existing
memory remains intact and the completed result exposes unresolved work and its
continuation status. A diagnostic alone never authorizes invented memory.

Runtime authority, storage, stale baselines, receipt verification and unexpected
programming errors are outside this business-validation boundary. Unknown
ValueError/TypeError/RuntimeError instances are not silently converted to success.
Confirmed storage readback and history remain mandatory for publication claims.

Provider-free tests invoke actual validators and the complete preparation/apply
path through the real runtime SDK fixture: the observed inference rejection,
changed statements/dates/locators/qualifiers, concurrent malformed synthesis,
same-role verified siblings, all-research exhaustion, and 60 malformed-field
combinations across research/critic/strategy/synthesis. They check final memory,
explicit verification labels, retained diagnostics, readback/history and global
limits. Historical tests and official package CI remain required. Fixture writes
are in-memory; no provider calls or live company writes occur during these tests.

Historical adapter/helper bytes and Agent, storage and authority contracts are
unchanged. Activate through the official intake promotion and runtime artifact
process. A terminal failed execution cannot be resumed as a new workflow under
the same UUID; its technical checkpoint must remain available for reconciliation.
Unexpected process failure before publication still cannot guarantee retention
of in-memory research. This release prevents typed content failures from causing
that whole-run loss; it does not add a separate business-data persistence store.
