# Company publication recovery 0.1.53

Version 0.1.53 requires runtime 0.1.123. It preserves the published 0.1.52 files,
prompts, role authority, provider policy, and fixed Skill reference.

Before publication, the adapter redacts only recognized sensitive spans from
generated memory and methodology drafts. Surrounding prose and public references
remain intact. The content-free receipt records original/new hashes, source text
ranges and categories. Removed values never appear in the receipt.

An affected paragraph loses its verified marker and published fact IDs. Safe
sibling paragraphs retain their status. A changed evidence annex or an attribution
that cannot be bounded safely removes all fact attestations while retaining the
draft as explicitly unverified research. Guidance IDs are recomputed from the
sanitized structured advice. The exact final candidates pass admission again.

SQL in inert research text does not confer query authority and is not a reason to
withhold publication. Required runtime controls, baselines, Core permissions,
readback/history checks and ambiguous-write reconciliation remain enforced.
Unclassified invalid content is not silently deleted. Optional invalid report
fields continue to use the existing receipt-based omission policy.

Initialization failures retain the SDK's closed safe proof, including request
stage, HTTP status, bounded attempts, accepted upload/operation references when
known, and whether reconciliation is required. No adapter exception text or raw
Core/provider response is copied. An ambiguous write is never replayed.

The historical rejection for company 346 cannot be reconstructed from the old
generic receipt. Version 0.1.53 improves evidence and recovery; qualification must
not be described as a repaired or confirmed historical publication.
