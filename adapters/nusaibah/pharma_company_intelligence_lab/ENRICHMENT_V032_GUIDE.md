# Objective

Contain an exhausted research backup within its original role so completed sibling research still reaches exact-source validation, section critics and existing Core Skill publication.

# System Context

Company-14 live run fb6d3611-6661-43b7-b47d-8c8181ddf38e completed under 0.1.31. Market JSON and its single backup were both rejected by the SDK. The research fan-out caught the original SDK error but not UnresolvedAgentResponse raised by the exhausted backup; the outer handler consequently retained an incomplete company and skipped the completed portfolio/regulatory work. No Skill package changed.

# Approach

Catch only the typed exhausted content response inside the existing research-role loop. Record its actual safe diagnostic and generate the established no-evidence projection for that role. Join and validate successful sibling results normally. Never represent failed Agent output as evidence, retry the backup, fabricate claims or convert negative critics into passes.

# Changes Made

Version-owned research and preparation entrypoints add the missing exception boundary. Reuse the complete original/backup contract wrapper, one-time resolver, section/subsection plans, literal chunks, exact spans, scoped critics, baseline-preserving candidates and Core Dynamic Skill CAS/history/readback capabilities. Benchmark stays disabled. Optional historical methodology is used where available; absence remains non-blocking.

# Modularity Impact

Historical source modules and contracts are unchanged. No Core, generic runtime, authority, provider or storage lane is changed. The asset version is additive; runtime remains 0.1.105 and delivery requires official workflow promotion.

# Validation

Regression scenarios cover each research role with both original and backup JSON rejected by the real SDK parser. Assert one backup only, actual failure diagnostics retained, successful siblings reach critics/synthesis, missing-role claims never enter candidates, supported siblings may publish and all-negative critics cannot publish. Original authority/transport failures remain strict. Deterministic tests do not prove live business publication.

# Risks / Open Questions

JSON mode and a backup cannot guarantee a provider returns usable content. Rejected raw text is not retained, so the original syntax cannot be reconstructed. A missing research role is not equivalent to not-applicable or full evidence completeness. Only independently validated surviving sections may publish. Exhaustion of a planner, strategy or synthesis dependency can still retain an incomplete company; other companies continue. Core Skill commits remain independent rather than cross-skill atomic. A corrected live cycle is required after promotion before declaring publication proven.
